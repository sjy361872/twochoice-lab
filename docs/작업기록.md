연습용 계산기(`C:\clove_oripa\pages\니부이치_계산기.html`)는 그대로 두고 새로 만들었다.

### 설계에서 고민한 것 (면접용 이야깃거리)
1. **정직성** — 성공 확률만 크게 보여주면 사람은 "유리하다"고 읽는다. 결과 카드에 실패 시 손실·평균 손익을 같은 크기로 붙였다.
   (연습용 계산기가 82% 를 초록색 "유리한 위치야"로 띄우던 문제를 고친 경험에서 나왔다.)
2. **"판별 확률"의 함정** — 처음엔 "이 판을 한 번 걸고 이후 최적" 값을 보여줬는데, 작은 판일수록 높게 나와(100pt 가 1위)
   오해를 불렀다. "이 판만 계속 누르면"으로 바꿨다. 작은 판은 DP 가 느려서 확산 근사를 썼는데, 목표가 한두 판 거리면
   78% vs 실제 70% 로 틀렸다 → 경계 overshoot 보정(목표 +이득/2, 바닥 −cost/2)을 넣어 시뮬레이션과 3%p 이내로 맞췄다.
3. **요청 예절** — 10/5 연습 프로젝트에서 2,000번 가까운 요청으로 클로브 API 429 차단을 겪었다.
   수집 스크립트는 목록 조회만(실행당 약 6번, 1.5초 간격), 429 면 즉시 중단, 이미 읽은 가챠는 다시 OCR 하지 않는다.
4. **OCR 한계** — 썸네일 글씨가 화려해 tesseract 로는 배당을 거의 못 읽는다(44개 중 확실한 건 몇 개).
   틀린 값을 그럴듯하게 띄우는 게 가장 위험해서, 신뢰도 0.5 미만은 빈칸 → 사용자가 썸네일 보고 입력, 자동값도 '확인' 배지.

## 2026-10-27 2차 — 무료 OCR 교체 · 참여 제한 제외 · 갱신 구조
- **OCR**: tesseract(배당 거의 못 읽음) → RapidOCR(PaddleOCR 모델 ONNX, 무료). 수집 스크립트를 파이썬으로 바꿨다(`scripts/fetch_nibuichi.py`).
  - 45개를 썸네일과 직접 대조하며 실수 유형을 고쳤다: 쉼표를 '.'/':'로 읽음 → 세 자리 묶음 정규화, '1/1.9'를 '11.9'/'1/1.S'로 읽음 → 패턴 추가,
    아래 띠 글자를 놓침 → 아래 띠·왼쪽 절반 확대 재판독, 틀린 값 → '그럴듯함 검사'(끝자리 100 단위·환원율 78~110%)로 신뢰도 깎기.
  - 결과: 45개 중 40개 자동 인식, **화면에 뜬 40개 전부 정답**(1/1.9 4개 포함). 틀리게 읽은 3개는 검사에 걸려 숨김, 2개는 못 읽음 → 사용자 입력.
- **참여 제한 제외**: 신규 가입 전용·1인/1일 횟수 제한·랭크 제한·충전 조건·잭팟 티켓 필요 가챠는 목록에서 뺀다(45 → 28개).
- **갱신 구조**: 1시간마다 Actions → 결과 JSON 만 `data` 브랜치에 커밋 → 사이트는 raw.githubusercontent 에서 바로 읽음(`VITE_DATA_URL`).
  코드 브랜치에 데이터 커밋이 안 쌓이고 재배포도 없다. 클로브 요청은 실행당 약 6번, 이미 읽은 가챠는 OCR 생략.

## 2026-10-27 3차 — 계산 점검 (`tests/audit.test.ts`, 15개 상황 × 화면값 ↔ 시뮬레이션)
발견하고 고친 것:
1. **격자 반올림 낙관** — 잔고가 계산 격자에 안 맞으면 가장 가까운 칸으로 '반올림'해서, 위로 올라가면 실제보다 유리하게 나왔다
   (27.5만→30만에 30000→54000만 반복: 표시 76.7% / 실제 68.2% — 275,000 을 276,000 으로 보고 '한 번 이기면 목표'로 계산).
   → 조회는 항상 내림, 잔고를 격자 단위(gcd)에 포함(`align`). '이 판만' 최대 오차 8.6%p → 표본오차 범위.
   ※ 연습용 계산기(clove_oripa)도 같은 코드라 같은 문제가 있다.
2. **추천 확률이 한쪽으로 0.2~1.2%p 높음** — 화면값은 '이번 판 이후 최적'인데 실제 추천은 0.3%p 안정화 규칙을 쓴다.
   → 추천 정책 그대로 따랐을 때의 확률(VP)을 계산해 표시. 15개 상황 전부 1.0%p 이내, 오차 방향도 위아래로 섞임(= 표본오차).
3. **평균 손익이 5~10% 작게** — 기대 잔고를 다른 정책(격자 argmax)으로 계산하고 있었다 → 추천 정책 + 실제 금액 이동으로 계산.
   남은 차이는 잔고의 1.5% 이내.
확인된 것: 최적 기법은 모든 상황에서 다른 기법(고정·마틴게일·파롤리·달랑베르)보다 높거나 같다. 켈리는 환원율 < 100% 에서 걸지 않고,
승률 58% 처럼 유리해지면 실제로 건다. 전 테스트 19개 통과.
